# AegisFlow — Optimization Opportunities (report only; nothing here has been applied)

Scope: read-only review, two days before the SIH deadline, with a working demo committed and pushed. This file lists what I found. You decide what, if anything, to touch.

Method and limits: I read every source file, config, test and report. I did not run the pipeline, the tests, or the server, so each "risk" is my estimate from reading the code, not a measurement. Unused-import findings come from a small AST scan plus manual grep (no linter is installed in `.venv`). Line numbers are as of this pass.

Rule I applied: if touching an item could plausibly break the demo path (`backend/app/*`, `index.html`, the saved artifacts, or the Parquet files the server reads), it is in Section B even if the fix is trivial.

## If you only do three things

1. **A1. Back up the demo's local-only files** (they are gitignored; the demo exists only on this laptop). Zero risk.
2. **A2. Fix the stale docs** (`docs/model.md`, `api.md`, `demo.md`, `architecture.md`, and banners on three superseded reports). Judges read these. Zero runtime risk.
3. **A3. Add `httpx` to `requirements.txt`** so a fresh install can run the backend tests. Near-zero risk.

### Safety checklist for any Section A change

1. Tag or note the commit that holds your known-good demo before touching anything (`git tag demo-freeze` — I could not run git from my session, so run it yourself).
2. Do docs-only items (A1, A2, A4, A5, A11, A12) in a separate commit from anything touching `.py`, `.yaml` or `requirements.txt`.
3. After any `.py` or `.yaml` edit: `python -c "from aegisflow.config import load_config; load_config()"`, then `python -c "import backend.app.main"` is **not** a free check (see B10: importing it starts model warm-up and opens the live DB), so instead start the server normally, wait for "model_ready", press Start at 1000×, verify the chain.
4. Running `pytest` is also not free: `backend/tests/test_audit.py` imports `backend.app.main`, which builds the app against the real ledger DB at import time. Take a copy of `data/processed/aegisflow.db` first.

### Things that look trivial but belong in B (so you are not tempted)

- Collapsing the duplicate `seq_end` assignment and the redundant `input_ends.max()` guard in `aegisflow/ml/temporal/sequences.py:175-185, 191-200`. Harmless duplication, but this is the leakage-critical function. Leave it.
- Removing the hard-coded benchmark branches in `aegisflow/ml/temporal/pipeline.py:118-121, 214-216`. They are never taken for the current data, so removal would be behaviour-identical, but it edits the preprocessing path, and the whole point of the freeze is not to regenerate those outputs. Just don't run `rebuild-temporal` (see walkthrough Appendix B).
- Single-sourcing the risk weights / 33-66 bands in `index.html`. Demo UI.
